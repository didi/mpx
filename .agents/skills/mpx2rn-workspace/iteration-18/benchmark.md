## 统计口径与验证边界

- 当前自动评分为 mpx 60/61（98.36%）、mpx2rn 59/61（96.72%）。根据用户实测修正了透明度判定：隐藏后恢复显示可以恢复点击，不能因某个动态分支或首帧为 0 就扣分。
- 本次只修正规则并重新评分原始输出，未重跑模型；分数变化不代表最近 Skill 优化已经得到验证。原输出和模型耗时、Token 指标未修改。
- mpx case 2 的 g8 改为通过：遮罩最终 opacity 为 1，卡片也在 nextTick 后恢复为 1。此前仅凭首帧透明扣分的结论已撤回。
- 用户提供的 RN 0.84.0 / iOS 26.2 模拟器测试显示同一节点 1→0→1 后事件恢复；0.001、0.01 在该环境也未命中。未由本次评审重新运行模拟器，也未把数值阈值推广到其他设备。
- 静态评分检查可确定持续为 0 的点击目标，不禁止动态隐藏/淡入。复杂动态表达式无法仅凭静态扫描证明展示后的可点击性，需要结合预期交互状态验证。
- 剩余失败为两组 case 0 的 l11，以及 mpx2rn case 1 的 j1。
- 修正前的 59/61 对照及复核意见保存在 scoring-before-opacity-correction/；最初的 53/61 与 56/61 原始评分保存在 scoring-before-fix/。
- 每用例每组只有 1 次运行。用例均值与按 61 条断言计分的总通过率口径不同；标准差来自不同用例，不是重复运行稳定性。
- Token 包含缓存输入，不等于计费量；耗时保留原子进程数据，不计本次复核与重评分耗时。
- 原输出 wx/iOS 编译无错误，评分组件有独立环境缺少全局组件注册的警告；UnoCSS 完整生成仍受本地 preset 异常阻断。未进行新的真机或模拟器验证。
