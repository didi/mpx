# Web 条件隔离

公共语法沿用 [Mpx 条件编译机制](../../../../docs-vitepress/guide/cross-platform/conditional.md)，这里不重复维护语法表、正反示例及条件注释配对规则。仅在具体写法不明确时查阅对应小节；Skill 安装位置不同导致相对链接不可用时，查阅目标项目同版本的 Mpx 文档，不转而依赖 RN 专项 Skill。

## 何时需要隔离

- DOM、浏览器对象、H5 SDK 或 Vue 组件等 Web-only 能力。
- 仅影响 Web 的路由、挂载、资源部署或 SSR 配置。
- 项目确实需要且其他目标端不支持的浏览器样式或交互。

已有通用实现没有差异时保持不变，不因为目标包含 Web 就增加条件分支。

## Web 边界

- 只隔离实际有差异的片段；按结构和依赖选择局部隔离或平台文件，不默认复制组件。
- Web 编译目标也可能运行在 SSR 服务端。浏览器对象与 SDK 初始化需确认处于浏览器环境，见 [SSR 专项参考](./ssr-reference.md)。
- Web-only 依赖应从其他目标的依赖图中隔离。静态导入是否合适取决于模块实际执行环境：确认只在浏览器执行、不会进入 SSR 或其他目标时，可以静态导入依赖浏览器全局对象的库；可能进入 SSR 时，模块顶层须能在服务端安全执行，否则应在客户端分支加载。`.web.mpx` 文件名本身不保证仅在浏览器执行。
- 依赖加载与 DOM 就绪是不同问题：即使可以静态导入，访问组件挂载节点的初始化仍需等待客户端挂载。SDK 生命周期与清理见 [H5 生态混合开发](./web-hybrid-dev.md)。
- 异步转换可能影响未命中分支的依赖删除，按公共文档的 [async/await 注意事项](../../../../docs-vitepress/guide/cross-platform/conditional.md#async-await-notes) 核对目标构建，不仅凭源码中的分支判断隔离成功。

验证入口统一见 [Skill 编译校验脚本](../SKILL.md#编译校验脚本)。静态检查、目标构建和实际运行分别记录，不相互替代。
