# Mpx2Ali 开发与适配

以现有微信实现和业务需求为基线，处理输出支付宝时需要业务适配的差异。优先复用 Mpx 已提供的转换能力，只为项目实际存在的差异添加局部适配。

## 任务识别

1. 从构建命令、配置和依赖确认输出目标、源码方言及 Mpx 版本。`mode: 'ali'` 表示支付宝输出，`srcMode: 'wx'` 表示微信源码方言；支付宝原生方言不能直接套用本 Skill 的转换结论。
2. 区分小程序宿主与设备系统。支付宝中的 iOS / Android 通过运行时系统信息判断；`__mpx_mode__ === 'ios'` 是 RN iOS 编译目标，不能用来判断 iPhone 上的支付宝。
3. 按任务读取下表命中的小节。新建或迁移完整页面、组件时核对模板、脚本、样式、JSON 四个区块；局部修复只检查受影响的部分。能力查询和方案讨论无需执行修改或构建。

## 适配原则

- **先核实框架是否已处理**：按本地仓库当前实现复用已有转换；自定义导航栏统一声明 `navigationStyle`，不再要求核实旧版导航转换能力或提供手动替代分支。文本与滚动条等能力仍核对实际产物，避免重复添加框架已有的兼容处理。
- **保留原平台行为**：优先共用节点、状态与事件链；单个属性有差异时用 `@ali` / `@wx` 限定该项，样式使用条件注释，动态 JSON 使用 `<script name="json">` 按目标赋值。保留原有组件注册和无关配置，不为局部差异复制整个页面。
- **按场景采用兼容方案**：输入框属性按宿主和设备系统选择；优先使用宿主自动上推，需要业务控制位移时避免与自动上推叠加。不要假设键盘事件固定顺序，也不要用统一延迟或固定键盘高度代替状态处理。
- **保留滚动职责**：支付宝禁止滚动的蒙层与可滚动弹层采用兄弟节点。关闭纵向回弹不等价于锁定页面滚动或关闭下拉刷新；只有业务需要固定页面框架时才调整根布局。
- **统一尺寸来源**：页面布局使用窗口尺寸，安全区计算核对坐标与单位。优先复用工程的公共系统信息封装，不把 `@mpxjs/api-proxy` 当作已包含所有业务尺寸归一和缓存逻辑。
- **保留证据边界**：历史机型问题、未复现问题和未真机验证的示例不能作为所有版本的固定限制。资料与工程不符时以目标版本和实际验证为依据，明确仍待核实的部分。

## 验证与交付

代码修改后，运行工程相关 ESLint、现有测试以及实际目标的构建；同时保留微信输出时检查微信与支付宝两端产物。导航栏重点核对生成的页面 JSON，条件属性和滚动结构重点核对模板产物。

文本默认换行与滚动条隐藏依赖完整 App 的兼容样式入口，不能仅凭单文件编译成功判定生效；独立分包、插件和单独编译的页面、组件需要在对应集成环境验证。滚动条值使用严格布尔值 `false` 才触发隐藏，`true` 不保证宿主强制显示滚动条。

涉及宿主渲染或交互时，按参考中的[真机验证关注点](references/mini-program-practice.md#真机验证关注点)覆盖项目实际支持的宿主与设备系统组合。交付说明修改点、执行过的检查及未验证范围；没有真机环境时，不声称键盘、滚动或安全区行为已通过验证。
